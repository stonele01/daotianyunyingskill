# 数据分析：Anthropic Data Analyst

本环节以授权提供的快手 Excel/CSV 为主要输入，抖音分开分析。复用原组件完成数据探索、计算和校验，中文交付。无需新界面、数据库或多 Agent；不把 db 经营诊断当报表计算。

## 读取哪些方法

- 每次数据分析读取 [analyze](../upstream/anthropic-data/skills/analyze/SOURCE.md)，执行理解问题、取得数据、计算、校验、解释的流程。
- 首次接触文件或数据结构变化时，读取 [explore-data](../upstream/anthropic-data/skills/explore-data/SOURCE.md)。已有核实的数据字典可复用，仍需检查本批日期和数据质量。
- 交付前读取 [validate-data](../upstream/anthropic-data/skills/validate-data/SOURCE.md)，实际复算关键数字，记录检查结果，不能只生成打勾清单。
- 涉及分布、趋势、异常或统计推断时读取 [statistical-analysis](../upstream/anthropic-data/skills/statistical-analysis/SOURCE.md)；需要图表时读取 [data-visualization](../upstream/anthropic-data/skills/data-visualization/SOURCE.md)。

原文 `/analyze` 等名称是方法入口，不要求员工换聊天、执行命令或安装五个独立技能。`~~data warehouse` 等是可选工具类别，不是本包已连接的服务；当前默认采用文件分支。原文提及的 sql-queries 和仪表盘不属于本包默认能力，不为读取 Excel 新建数据库或生成 SQL。文件分析由宿主可用代码执行工具完成，见 [工具接入](tools.md)。

## 先弄清楚数据代表什么

读取用户明确提供的文件或目录，原始文件保持不变。确认业务问题、平台、导出页面、时间范围、每行粒度、账号/商品/素材关联键；ID 按字符串保留。口径不清楚且影响结论时集中询问，其他可确定的检查先做。

按照 explore-data 检查工作表、表头、数据类型、空值、重复、合计行、日期覆盖和粒度。重复候选不自动删除，退款负数不自动改正，缺失值不补成 0；清洗记录原行与处理理由。

把实际字段映射为 `原文件/工作表｜原字段｜业务含义｜单位｜粒度｜时间/归因口径｜处理方式｜确认状态`。映射来自数据说明或用户确认，不能单凭列名猜测“成交金额”属于支付、结算或退款后金额。金额/百分比解析保留原单位，中文图表和人民币仅在确认单位后使用。

## 快手与电商适配

- 平台、统计周期、归因窗口、退款成熟度一致时才直接比较；不同口径单列。没有退款字段不能称退款后收益，没有成本不能称利润。
- 使用用户或后台定义计算 ROI/ROAS 等指标，写清分子、分母、时间范围和过滤条件。不把成交/消耗比直接当利润率，不把同名字段跨平台合并。
- 汇总比率优先按明确口径汇总分子、分母再相除。不能平均素材 ROI 得到账户 ROI；零分母、未成熟周期、样本不足单列。
- 合并文件前检查关联键和一对多关系，避免将消耗与多个订单连接后重复累计。无法可靠关联则分别分析，不能按相似标题硬匹配。
- 判断素材表现时结合商品、目标、消耗、转化样本、退款和利润约束；没有足够条件只输出排序及继续测试建议，不套固定 ROI 或消耗门槛。
- 上游空值阈值、30 个事件等是启发示例，不是通用验收线。百分比可能是大于 100% 的增长率；净额可能因冲减为负。按字段定义判错。
- 统计显著性不证明因果，也不保证值得投放。控制时间、人群、价格、活动等影响；观察数据中的解释标为待验证假设。少量数据不强做显著性检验或预测。

## 实际计算与交付

在任务目录保存本次分析代码或可复算公式；大文件用代码处理，不把截断预览当完整数据。已有汇总能回答问题时不重复建立复杂模型。

简单查询给结果、来源和计算依据即可。完整分析按 [交付约定](deliverables.md) 输出 analysis/：

- `field-map.csv`：字段与口径，以及重要待确认项；
- `summary.csv` 或 `summary.xlsx`：可追溯的汇总和筛选结果，格式按用户需要；
- `report.md`：核心发现、数据依据、异常、解释假设、限制、建议；
- `calculation.py` 或公式说明：实际计算过程；
- `validation.md`：原组件要求的关键检查、复算数字、差异处理与未覆盖项；
- 必要时生成图表，图表保留来源、单位和统计范围。

无代码执行能力时只能核对可见内容或交付计算方案，不能伪称已完成全表计算。没有文件时列出本次最少样本要求，不制造演示结论或节省比例。

## 把复盘交回内容工作

用户要求复盘时，将报表素材 ID 对应到作品链接、candidate_id、script_id 和版本；缺映射的单列。数据可用但没有视频时，只给数据层诊断，不推断具体开头、镜头或口播问题。

结合已有视频证据与 [db 内容诊断](../upstream/dbskill/dbs-content/SOURCE.md)，把每条建议写为 `观察事实｜可能解释｜下一轮要改变的一个变量｜需保持一致的条件｜评价指标及观察窗口｜证据强度`。观察窗口依据业务和样本确定，不预设通用值。

保存 `analysis/next-round.md`。下一轮搜索把它用作筛选约束；写稿时把它交给 [脚本与审核](production.md)，沿用商品事实和版本。最后按 [内容资产](review-assets.md) 归档已核实案例及反例。用户仅要求分析表格时到分析交付为止，不自动扩大为脚本生产或投放操作。

# 输入产品，实际查找同款作品

此流程用于“找这个产品的爆款视频”。它调度已有浏览器、搜索或用户已授权的数据服务，不要求新建爬虫系统。

## 1. 把产品转成可核对的检索目标

从用户文字、商品链接、包装图片或已有事实卡提取品牌、完整名称、系列/型号、规格、包装特征及别名。把每项信息的来源记到 brief.md。图中小字看不清就保持未知，不补造型号。名称有多个明确不同的商品且会改变搜索方向时，只问缺的那一项；不要为了搜索索要完整功效证明和拍摄资源。

先用“品牌＋系列/型号”“品牌＋通用商品名”，再用有依据的中文名、英文名、简称和常见别名。功效词和场景词可以帮助召回，但不能替代品牌或型号。搜索“OR 控油洗发水”与“控油洗发水”是两个范围，记录清楚。

## 2. 使用能取得实际作品的入口

按 tools.md 选择宿主允许的浏览器或已经配置的 web-access。进入目标平台，通过实际页面上的搜索框、作品结果、筛选和详情页操作；不根据记忆拼接未验证的筛选参数。不在不支持的宿主上另启浏览器自动化绕过工具限制。

- 快手、抖音分别搜索和保存结果。某个平台暂不可读时，不把另一个平台的结果冒充交付。
- 普通网页搜索可发现公开作品链接；打开作品页核查后再入候选。主页、广告落地页和只有摘要的结果留在线索表。
- 若宿主允许读取页面已正常加载的结构化数据，保留来源 URL、观测时间和字段含义；不读取凭证或绕过验证码、权限、付费墙。用户已有授权的稳定 API 可作为替代入口。
- 工具报错先核对响应、页面及当前连接状态；一次针对性修正无改善就换已有入口或如实报告缺口，不无限重启代理。连接成功、页面标题出现均不能替代作品结果。

使用当前环境已准备好的工具。若用户已有搜索脚本，先读源码确认参数、输出和副作用；不能因脚本名包含“爆款”就直接运行。可用配置或很小的适配解决问题时，复用原工具。不要把某台电脑的浏览器路径或某次产品关键词写成整个包的通用默认值。

## 3. 获取、筛选、排序

先读小批量结果，判断关键词是否命中产品，再决定是否翻页或换别名。记录查询词、界面实际排序、筛选条件、已查看页/条数和停止原因。有些页面会丢弃 URL 筛选参数，必须以实际界面和作品日期复核。

打开候选作品，核查标题、画面包装、商品关联信息中至少足以确认产品的证据。品牌相同但系列不清时记“待核实”。仅凭搜索命中不记“确认同款”。

记录每条作品链接、ID、作者、日期、当前可见赞评藏转、时长、产品匹配证据；不可见项为空并注明。单位由当前来源确认，不能固定认为 video.duration 都是毫秒。不要将原声标记当成口播检测结果，也不将平台隐藏的 0 值视为真实零播放。

用平台＋作品 ID 去重，保留查询词来源。更新指标时保留对应观测时刻，不从不同时刻分别挑最高值拼出一条“最优”快照。置顶、老作品、推广来源未知的样本单独标注。

在确认同款的样本内，按用户目标与实际可得指标排序，说明比较范围。没有播放数据时，“收藏/点赞”就是藏赞比，不叫收藏率。只有互动数据时称“本次样本中高互动作品”，不推断销量、盈利或完播。判断相对高表现优先参考可比作品分布；不内置统一爆款阈值或强制 31–90 天窗口。

## 4. 交付与衔接

candidates.csv 至少包含：

`candidate_id｜platform｜video_id｜source_url｜author｜title｜published_at｜observed_at｜query｜product_match｜product_evidence｜likes｜comments｜favorites｜shares｜duration_seconds｜metric_source｜missing_fields｜evidence_status`

selection.md 说明实际搜索范围、产品识别依据、首选作品及理由、筛选和排序口径、覆盖限制。同款不足时清楚给实际数量和待核项，不拿近似产品凑数。

用户要继续拆解时，沿用 candidate_id 取得视频、读取声音与画面；用户还要求写稿时把结构发现直接交给 production.md。无法取得视频时，交付中只能称作品数据/封面分析，不能称已经完整看过视频。

## 现有抖音搜索脚本的复用注意

2026-09-27 查看用户提供的 WorkBuddy 记录及其已有 douyin-viral-research：可以复用“查询多个关键词→收集作品级结果→按 ID 去重→详情核对”的方法。被查看版本的脚本存在硬编码关键词、浏览器与输出路径，且缺失指标置零。使用前须把这些改成实际任务参数或保留缺失值；未检查的 API 价格和站点行为不写成当前承诺。该脚本不等于快手适配器。
